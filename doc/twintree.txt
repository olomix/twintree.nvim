INTRODUCTION                                            *twintree-introduction*

twintree.nvim shows a git diff in a tab with three columns: a tree of changed
files, the version before the change and the version after it.

Both versions are real files on disk. The old version is checked out into a
git worktree, so language servers work on it: go-to-definition, references
and hover show how the code worked before, independently of how it works now.

==============================================================================
REQUIREMENTS                                            *twintree-requirements*

- Neovim 0.11 or newer
- git
- Optional, for icons: `nvim-web-devicons` or `mini.icons`, and a Nerd Font

==============================================================================
COMMANDS                                                    *twintree-commands*

                                                                    *:Twintree*
:Twintree [rev1 [rev2]]
    Open a diff for the repository that contains the current directory.

    Arguments      Before                         After ~
    (none)         HEAD                           working tree
    rev1           merge-base of rev1 and HEAD    working tree
    rev1 rev2      merge-base of rev1 and rev2    rev2

    The merge-base is always used, as in `git diff rev1...rev2`. To review a
    branch, `:Twintree main` shows what the branch changed since it left
    main. When rev1 is an ancestor of the other side, the merge-base is rev1
    itself, so `:Twintree HEAD~3` compares with exactly that commit.

    The diff opens with the first file of the tree shown in both panes, as
    after `<CR>` on its line, and the cursor in the after pane. When nothing
    changed, or when that file is not opened (see |twintree-swap|), the
    panes are empty and the cursor is in the tree.

    A file that is shown for the first time, when the diff opens or after
    `<CR>` in the tree, has the cursor on its first change, which can be
    the first line. The jump list gets no entry. A file the diff has shown
    before
    has the cursor where it was left. A file reached by a jump (definition,
    quickfix entry, `:edit`) keeps the cursor of the jump and counts as
    shown. An added or deleted file is shown from its top.

    The diff opens in a new tab. When Neovim was just started and shows only
    an empty buffer, that tab is used instead: >

        nvim +Twintree
        nvim +"Twintree main"
<
    To end the diff, close its tab with `:tabclose`. The worktree stays
    cached. When the diff is the only tab, as after `nvim +Twintree`,
    `:tabclose` refuses to close the last tab; quit Neovim with `:qa`.

    When no other diff uses that worktree, the buffers of its files are
    wiped out and its language server is stopped, see |twintree-lsp|. A
    buffer stays when a window still shows it, when a quickfix or location
    list refers to it, or when it has unsaved changes; it goes when a later
    tab is closed and that is no longer so. Files of your working directory
    are never touched.

                                                          *:TwintreeToggleTree*
:TwintreeToggleTree
    Hide the tree of the current diff tab, or show it again. The tree is
    shown as the leftmost window with the width it had, and the cursor is
    placed on the selected file. The diff keeps working while the tree is
    hidden. Closing the tree window with `CTRL-W c` hides it as well.

                                                         *:TwintreeResetLayout*
:TwintreeResetLayout
    Return the current diff tab to its original view: the tree, the before
    pane and the after pane, in that order and nothing else. Every other
    window of the tab is closed; the buffers they showed stay loaded, also
    when they have unsaved changes. The tree gets its configured width, the
    panes are made equally wide, and the file the panes compared is shown
    again, also when it is not one of the changed files. Folded directories
    are kept.

    Use it when the tab got into a state you do not want, or when the plugin
    reports that a pane is missing.

Both commands report an error when the current tab has no diff.

                                        *:TwintreeNextFile* *:TwintreePrevFile*
:[count]TwintreeNextFile
:[count]TwintreePrevFile
    Show the next or the previous changed file of the current diff tab in
    both panes, as `<CR>` on its line in the tree does, except that the
    current window stays the current one. With a count, move that many
    files; a count past the end stops at the last file.

    The files come in the order of the tree. Files inside a folded
    directory are skipped, also when the file shown now is inside one.

    When the panes show a file that is not in the tree, for example after
    a jump to a definition, the commands continue from the changed file
    that was shown last. When none was shown yet, next goes to the first
    file and previous to the last.

    The commands do not start over at the ends. When there is no file to
    go to, one of these is reported and nothing changes:

        no more changed files ~
            The first or last file was reached.
        no changed files ~
            The diff has no changed files.
        every changed file is in a collapsed directory ~
            Unfold a directory in the tree.

    Default keys: see |twintree-keys|.

                                       *:TwintreeFirstFile* *:TwintreeLastFile*
:TwintreeFirstFile
:TwintreeLastFile
    Show the first or the last changed file of the tree that is not inside
    a folded directory. No key is mapped to them by default: >lua

        vim.keymap.set("n", "]<C-g>", "<Cmd>TwintreeLastFile<CR>")
<
    `]<C-S-f>` works only in a terminal that tells Ctrl+Shift+F from
    Ctrl+F, see |tui-csiu|. Elsewhere Neovim receives `]<C-f>`, and the key
    shows the next file instead of the last.

                                                            *:TwintreeCopyPath*
:TwintreeCopyPath [{form}]
    Copy a path to the clipboard, register "+", and show what was copied.
    {form} is one of:

        relative    The path from the repository root. The default.
        absolute    The full path of the file.
        name        The last component of the path.

    In the tree, the path is that of the file or directory on the line of
    the cursor. Elsewhere in the diff tab, it is that of the file the panes
    show, also when the tree does not list that file. A file outside the
    repository has no relative path.

    The absolute path is the file of the after side, or of the before side
    when the file or directory exists only there, as for a deleted file.
    It is a path with symbolic links resolved.

    Without a clipboard provider the command says so, see |clipboard|. Two
    things it cannot tell: a clipboard tool that fails after it was
    started, and a `g:clipboard` set to false, with which "+" is an
    ordinary register.

                                                               *:TwintreeClean*
:TwintreeClean
    Remove the cached worktrees of the current repository. Worktrees used by
    an open diff are kept. See |twintree-worktrees|.

==============================================================================
LAYOUT AND KEYS                                               *twintree-layout*

Tree window (left):

    <CR>    On a file: show it in both panes and move to the after pane.
            On a directory: fold or unfold it.
    <2-LeftMouse>
            A double click on a line does what <CR> does there.
    R       Recompute the list of changed files.

    A single click, a drag and a triple click are not mapped: they move the
    cursor and select text as in any buffer. A double click selects no word
    in the tree.

    A buffer-local key that you map for the filetype `twintree` in a
    |FileType| autocommand replaces the key of the plugin.

                                                               *twintree-menu*
    The menu of the right mouse button, see |popup-menu|, starts with three
    items when it opens in normal mode on a file or directory line of the
    tree:

        Copy relative path
        Copy absolute path
        Copy file name

    They run |:TwintreeCopyPath| for the line of the cursor. With
    'mousemodel' "popup_setpos", the default, that is the line you clicked.
    With "popup" the cursor does not move, and the items appear only for a
    click in the tree window you are in. With "extend" there is no menu.
    The items are not in the menu anywhere else, and the plugin changes no
    other item.

Anywhere in a diff tab, in normal mode:                        *twintree-keys*

    ]<C-f>  Show the next changed file, as |:TwintreeNextFile|.
    [<C-f>  Show the previous changed file, as |:TwintreePrevFile|.

    Both take a count. The keys are set with the `keys` option of
    |twintree.setup()|.

    The keys exist only while a diff tab is the current tab. When another
    tab becomes current, the global normal-mode mapping you had on a key
    is put back, with its options and description, and a key you had not
    mapped is unmapped again.

    Only normal mode is touched. A mapping made with `:map` keeps working
    in every mode; afterwards `:map` lists it as two entries, one for
    normal mode and one for the other modes.

    A buffer-local mapping on the same key, of yours or of another plugin,
    takes precedence in that buffer. Choose other keys if needed.

    When you map or unmap one of the keys while a diff tab is current, the
    plugin leaves that key alone, in this and in other diff tabs, until
    the next call to |twintree.setup()|.

    The keys follow changes of tab that fire the |TabEnter| event. After a
    change that fired none, as with `:noautocmd tabnext`:
    - outside a diff, the first press of a key only removes the plugin's
      mappings; the next press is handled by your mapping or by Neovim;
    - in a diff tab the keys are missing until the next change of tab.
    The commands work in both cases.

A line of the tree shows, from left to right: an indent guide per level of
nesting, the icon, the name, the lines added and deleted, and the status
letter at the right edge of the window: >

    ▾ commons/
    │ json.go                  +9 -4 M
    │ json_test.go           +23 -18 M
    ▾ db_migrations/ams/             A
    │ kz_028_prom…_events.sql +40 -0 A
    ▾ pkg/
    │ client.go ← api.go      +12 -3 R
<
Status letters: A added, M modified, D deleted, R renamed. Untracked files of
the working tree are listed as added. A directory that contains only one
directory is shown together with it on one line.

A directory that exists on one side only has a letter in the column of the
status letters, in the colour of that status: A when it is missing on the
before side, D when it is missing on the after side.

Line counts are the lines added and deleted between the two sides. An
untracked file counts as all lines added. A binary file, an untracked file
larger than 5 MB, and a file that was removed from the index but is still on
disk show no counts.

Icons are shown when |twintree-icons| finds an icon plugin. Directories then
have folder glyphs in place of the arrows.

A name that does not fit is cut in the middle, so that its beginning and its
extension stay visible. The tree is drawn for the width of its window and
drawn again when that width changes, so widening the tree shows more. It is
also drawn again when line numbers, a sign column or a fold column are
switched on in its window.

A renamed file shows where it came from after its name, when the whole line
still fits: the old file name for a rename within a directory, the old path
otherwise.

When a line does not fit it gives up, in this order: the rename origin, the
middle of the name down to ten cells, the line counts, more of the name. The
status letter is always shown.

Before and after panes:

The selected file is shown in diff mode in both panes, in full: unchanged
lines are not folded. Use `zi` in a pane to switch folding on and see only
the changes with context.

                                                              *twintree-follow*
The panes are normal windows, and they stay a diff wherever you go. When a
file enters one pane, for example with go-to-definition, a quickfix entry or
`:edit`, the other pane shows the same file from its side:

    - A file that did not change is shown on both sides without differences.
      A file that is one of the changed files is marked in the tree.
    - A file always goes to the pane of its side. A file of the before side
      opened while the cursor is in the after pane appears in the before
      pane, and the cursor goes with it.
    - A file outside both sides, such as a dependency, is shown in both
      panes.
    - A file that does not exist on the other side is shown next to an empty
      pane.
    - A buffer that is not a file, such as a terminal, gets a plain pane.

The tree window only shows the tree: `:edit` there is refused by
'winfixbuf', and a quickfix entry opened from it goes to the panes.

To keep another file next to the diff, open a window of your own with
`:split`. Such a window does not follow and is not part of the diff.

When the after side is the working tree, its buffers are the files of your
checkout and can be edited. Files of a worktree are read-only.

Swap files:                                                    *twintree-swap*

A file of your checkout that a pane is about to show may have a swap file.
When the file is open in another Neovim that is still running, it opens as
usual and Neovim prints its warning W325. You can edit the file in both; the
second one to save is warned that the file changed on disk.

For any other swap file, such as one left by a crash, the plugin asks. The
prompt shows what Neovim's own |E325| message shows and offers the same
choices: Open Read-Only, Edit anyway, Recover, Delete it, Quit and Abort.
Delete it is not offered while the process that owns the swap file is
running.

After Quit or Abort the file is not opened and one line says so. After a
selection in the tree, the panes show what they showed before. When it was
the file a diff opens with, the diff still opens, with empty panes and the
cursor in the tree, and the file can be selected again. After a jump
in a pane, that pane keeps the file you went to, without diff mode, and the
other pane keeps its file; going back restores the diff, and going to the
file again asks again.

The prompt appears only for files the plugin itself puts into a pane. Files
you open keep Neovim's own dialog. Files of a worktree use no swap file.

Windows:                                                    *twintree-windows*

The diff tab is yours: resize, zoom, split and close windows as in any other
tab. Neovim's own window commands do most of the work:

    CTRL-W t    Go to the tree (the top-left window). While the tree is
                hidden this is the before pane.
    CTRL-W p    Go back to the window you came from.
    CTRL-W =    Make the before and after panes equally wide. The tree
                keeps its width.
    CTRL-W |    Maximize the current window. CTRL-W = brings the layout
                back: the tree at its width, the panes equally wide.
    CTRL-W c    In the tree: hide it. See |:TwintreeToggleTree|.

The plugin keeps the following:

- The ratio between the before and the after pane when the terminal is
  resized. It starts at half and half. Resizing a pane changes it, CTRL-W =
  sets it back to half and half.
- The width you give the tree. It is restored after a zoom. A tree squeezed
  to one column is treated as the leftover of a zoom and widened again on the
  next CTRL-W =, so hide the tree instead of squeezing it.
- A maximized window is not maximized again after a terminal resize; press
  CTRL-W | once more.

|:TwintreeResetLayout| returns the tab to its original view.

When a pane is closed, showing a file reports that a pane is missing and
names |:TwintreeResetLayout|. That also holds when an autocommand, of yours
or of another plugin, closes a pane while the plugin is showing a file: the
file that was selected before stays selected, and the pane that is left
shows what it showed, without diff mode. When the diff tab itself is closed
at that moment, one line says so. A pane that is alone in its diff tab is a
plain window: it is in diff mode only while both panes are there.

Highlight groups, linked by default:

    TwintreeAdded        Added
    TwintreeModified     Changed
    TwintreeDeleted      Removed
    TwintreeRenamed      Special
    TwintreeDirectory    Directory
    TwintreeSelected     Visual
    TwintreeGuide        NonText
    TwintreeOrigin       Comment

Line counts use TwintreeAdded and TwintreeDeleted. An icon uses the highlight
group its plugin gives it.

==============================================================================
CONFIGURATION                                          *twintree-configuration*

                                                             *twintree.setup()*
Calling setup is optional. Defaults: >lua

    require("twintree").setup({
      -- Width of the tree window.
      tree_width = 35,
      -- Directory for cached worktrees.
      -- Default: stdpath("cache") .. "/twintree"
      cache_dir = nil,
      -- Icons in the tree, when an icon plugin is installed.
      icons = true,
      -- Keys bound while a diff tab is current, see |twintree-keys|.
      -- false leaves an action without a key.
      keys = {
        next_file = "]<C-f>",
        prev_file = "[<C-f>",
      },
    })
<
A call with a value that cannot be used, such as an empty key or the same key
for both actions, is reported in one line and changes nothing. A call made
while a diff tab is current takes effect at once.

After the Lua modules of the plugin are reloaded, call setup again; until
then the default keys apply.

                                                               *twintree-icons*
Icons come from `mini.icons` or `nvim-web-devicons`, whichever is installed;
`mini.icons` is used when both are. Neither is required. Most icons and the
folder glyphs need a Nerd Font. Set `icons = false` to switch them off, for
example when your terminal draws a glyph wider than one cell and the columns
no longer line up.

Lua API: >lua

    require("twintree").open({ "main" })  -- same as :Twintree main
    require("twintree").clean()           -- same as :TwintreeClean
<
`open()` returns the tabpage of the diff, or nil and a message when the diff
did not open. When the diff opened but its first file was not shown, it
returns both the tabpage and the message; `:Twintree` prints it.

==============================================================================
WORKTREES                                                  *twintree-worktrees*

Every side that is a commit is a git worktree with a detached HEAD, stored at
>
    <cache_dir>/<repository>-<hash>/<commit>
<
Worktrees are kept after the diff is closed and reused the next time the same
commit is needed, so reopening a diff does not check the commit out again.
They are registered in your repository and appear in `git worktree list`.
They lock no branch.

Use |:TwintreeClean| to remove them. Worktrees of a repository that no longer
exists can be deleted from the cache directory by hand.

==============================================================================
LANGUAGE SERVERS                                                 *twintree-lsp*

The plugin starts and configures no language server. A worktree has the same
root markers as your checkout, so your LSP configuration starts a second
client for it. Check with `:checkhealth vim.lsp` that the two sides use
clients with different roots.

When a tab is closed and no diff uses a cached worktree any more, the plugin
wipes out the hidden buffers of its files and stops the clients of Neovim's
built-in LSP client that have no buffer left and work on nothing but such
worktrees. A server of your working directory is never stopped. Opening a
diff of the same commit again starts the server again.

A server that was still starting when the tab was closed keeps running; it
is stopped when the next tab is closed. Language servers of other LSP
clients (coc.nvim, ALE) are not stopped.

==============================================================================
LIMITATIONS                                              *twintree-limitations*

- Files that git does not track are missing in worktrees: `node_modules`,
  virtual environments, build output, generated code. Language servers that
  need them work only partly on the old side.
- Checking out a worktree for the first time blocks Neovim until git is done.
- Submodules, Git LFS and sparse checkouts are not handled. An untracked
  nested git repository is not listed.
